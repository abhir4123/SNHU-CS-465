# SNHU-CS-465

## Architecture
In building the Travlr Getaways project, I worked with two different frontend approaches: Express with Handlebars templates and Angular as a single-page application (SPA). The Express side generated dynamic HTML for the customer-facing pages, while the Angular SPA provided a faster and more interactive experience for administrators by updating the page without full reloads. The backend used MongoDB because its NoSQL, document-based design was a natural fit for storing trip data, which could be represented as JSON documents and easily adjusted without rigid schemas. This made it simpler to integrate the database with the RESTful API and keep the architecture flexible and scalable.

## Functionality
JSON was a key piece that tied the frontend and backend together, acting as the standard format for sending and receiving data between the Angular SPA, the Express API, and MongoDB. Unlike JavaScript, which is a programming language, JSON is only a lightweight data format, but its similarity to JavaScript makes it easy to parse in the browser. During development, I refactored code to improve functionality and efficiency, such as centralizing login logic in an Authentication service and creating reusable UI components like TripCard. These changes made the application easier to maintain and expand, while also improving consistency in how data and features were presented to the user.

## Testing
Testing required verifying both endpoints and security. Using Postman, I tested GET requests for retrieving trips, POST requests for creating new trips or registering users, and PUT/DELETE requests for updating or removing trips. Once JWT authentication was added, I tested again with tokens by logging in, copying the token, and attaching it as a Bearer header to confirm that protected endpoints worked only when authorized. In addition to endpoint testing, I verified the SPA itself by running Angular, logging in through the UI, and checking that requests included the Authorization header automatically via the interceptor. This process showed how methods, endpoints, and security measures all interact in a full stack application.
